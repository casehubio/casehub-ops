# Level 01: Hello LLM

**Methodology step:** DEPLOY — First App
**Prerequisites:** None
**Use case companion:** [UC01 Customer FAQ Agent](../../use-cases/UC01-customer-faq-agent/)

## When to use this pattern

You need a running LLM app. Four services — manifest, eidos, engine, and the LLM app itself — form the minimum viable CaseHub deployment. This is where you start.

## Walkthrough

1. Deploy four services via claudony: manifest (app descriptors), eidos (agent knowledge), engine (execution runtime), my-llm (the LLM app)
2. Dependency ordering ensures correct startup: manifest first (no dependencies), eidos after manifest, engine after eidos, my-llm after engine
3. Observe that each service registers with claudony and reports a healthy status
4. Send a prompt to the LLM — it responds using the identity briefing generated by eidos from application metadata
5. Check the audit trail — each deployment event is recorded

## Verify after deployment

1. All 4 services registered with claudony
2. Deployment order respects dependency edges (manifest → eidos → engine → my-llm)
3. LLM responds to prompts using the eidos-generated briefing
4. Each service reports a non-ABSENT status

## Common failure modes

- Service not registered → check claudony connectivity and that the deployment target is reachable
- Wrong deployment order → check `dependsOn` edges in the YAML topology
- LLM has no identity or responds generically → verify eidos descriptor resolution and that the descriptors.yaml is on the classpath
